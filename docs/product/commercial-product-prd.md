# RunbookIQ 商业化产品 PRD

状态：执行中  
版本：v0.2  
更新时间：2026-07-31

## 1. 产品判断

RunbookIQ 不应定位为“又一个可以上传文件的聊天机器人”，而应定位为：

> 面向 20–200 人、知识密集且缺少专职 AI 团队的企业，提供可独立部署、按企业隔离、回答可追溯的知识工作台。

首个垂直切入仍采用项目已有优势：运维、零售运营、制度手册等对“答案正确且能找到原文”要求高的内部场景。现阶段不承诺金融、医疗、政府等强监管行业的完整合规能力。

## 2. 核心用户与 JTBD

### 企业所有者 / 知识管理员

当企业资料散落在文档和个人经验中时，我希望在 15 分钟内建立一个可搜索、可问答的独立知识空间，并邀请同事使用，从而减少重复咨询和查文档时间。

### 企业员工

当我需要执行制度或处理业务问题时，我希望直接提问并看到答案对应的原文证据，从而更快完成任务且不盲信模型。

### 平台运营者

当多个客户运行在同一服务器时，我希望企业、成员、域名、知识库和评测集都严格隔离，并能观察成本与质量，从而安全地扩展客户数量。

## 3. 用户价值闭环

```text
注册企业
  → 自动获得专属网址和默认知识库
  → 上传第一份真实文档
  → 提出业务问题并核验证据
  → 邀请同事
  → 团队持续使用
  → 管理员用评测集验证质量
```

本轮优先完成前五步。没有“同事加入并持续使用”，产品只能算个人演示，不能算企业产品。

## 4. 北极星指标与漏斗

北极星指标：**每周有效证据回答数（Weekly Verified Answers）**。

“有效证据回答”必须同时满足：

- 查询成功完成；
- 至少返回一个可查看证据；
- 用户未标记为无帮助，或后续补充的自动忠实度门禁通过。

首批需要埋点的指标：

| 阶段 | 指标 | 初始目标 |
|---|---|---:|
| 注册 | 注册成功率 | ≥ 95% |
| 激活 | 注册到首次文档上传转化 | ≥ 60% |
| 首次价值 | 注册到首次证据回答的中位时长 | < 15 分钟 |
| 协作 | 产生首条回答后创建邀请的企业占比 | ≥ 25% |
| 协作 | 邀请 7 日接受率 | ≥ 60% |
| 留存 | 企业 D7 有效证据回答留存 | ≥ 35% |
| 质量 | 无证据回答率 | < 5% |
| 安全 | 跨企业越权成功次数 | 0 |

这些是产品假设，不是当前实际数据；在埋点上线前不得把它们作为已实现成绩写入简历。

## 5. 本轮范围：企业激活与团队协作

### 问题

此前新企业注册后进入空知识空间，需要自行理解下一步；企业所有者也无法邀请同事。因此产品只能完成“负责人个人试用”，不能完成真实的企业推广。

### 解决方案

- 注册成功时自动创建一个属于该企业的默认知识库；
- 知识库页显示“上传文档 → 首次提问”的三步引导；
- 所有者和管理员可以生成 7 天有效、只能使用一次的邀请链接；
- 受邀用户在企业专属网址设置密码后进入同一企业；
- 支持所有者、管理员、内容编辑者、只读成员四种角色；
- 服务端强制角色权限，不能仅靠前端隐藏按钮；
- 团队页展示企业专属网址、正式成员和待接受邀请。

### 权限矩阵

| 能力 | 所有者 | 管理员 | 内容编辑者 | 只读成员 |
|---|:---:|:---:|:---:|:---:|
| 知识问答、查看证据 | ✓ | ✓ | ✓ | ✓ |
| 上传文档、运行评测 | ✓ | ✓ | ✓ | — |
| 创建知识库 | ✓ | ✓ | ✓ | — |
| 删除知识库 | ✓ | ✓ | — | — |
| 查看成员 | ✓ | ✓ | ✓ | ✓ |
| 创建/撤销邀请 | ✓ | ✓ | — | — |

### 安全与非功能要求

- 邀请 token 至少 256 bit 随机性，数据库只保存 SHA-256 摘要；
- token 放在浏览器 URL fragment 与 API 请求体中，不进入页面或 API 访问路径日志；
- 邀请 7 天过期、接受一次后立即失效、可由管理员撤销；
- Cookie、CSRF、同源校验沿用现有生产安全策略；
- 所有成员数据按 organization_id 查询；
- 无权限写操作返回 403，跨企业知识库仍统一返回 404；
- 生产迁移必须可在已有 PostgreSQL 数据卷上重复执行。

### 明确不在本轮范围

- 自动发送邀请邮件；
- 手机验证码、邮箱验证、忘记密码；
- 成员移除、角色变更和所有权转移；
- SSO / SCIM；
- 套餐、支付和发票；
- 企业自定义 Logo、主题和独立顶级域名。

## 6. RICE 排序结论

RICE 的输入保存在 [rice-backlog.csv](rice-backlog.csv)。由于当前没有真实客户量，Reach 和 Confidence 是产品假设，只用于比较，不代表市场事实。

1. 默认知识库与首次使用引导：覆盖所有新注册企业、成本低，立即实施；
2. 成员邀请与 RBAC：决定产品能否从个人演示进入企业协作，立即实施；
3. 文档来源管理：让管理员查看、重建索引和删除来源，下一阶段；
4. 用量、配额与成本看板：商业收费和服务器容量管理的前提；
5. 审计日志与备份恢复：进入付费试点前必须完成；
6. 品牌与自定义域名：有销售价值，但不应早于安全、用量和恢复能力；
7. 计费套餐：在验证 3–5 家持续使用的设计伙伴后实施；
8. SSO / SCIM：等到目标客户明确要求或合同驱动时实施。

## 7. 分阶段路线图

### Phase A：可用的企业试点（当前）

- 企业注册、登录、租户隔离和专属子域名；
- 默认知识库与首次使用引导；
- 一次性成员邀请与角色权限；
- 文档摄取、证据问答和知识库专属评测；
- CI/CD、HTTPS 和生产健康检查。

### Phase B：可运营的付费试点

- 文档来源列表、状态、删除、重新摄取和失败重试；
- 查询、文档、存储和模型 token 用量；
- 套餐配额、限流和超额保护；
- 操作审计日志；
- PostgreSQL 自动备份、恢复演练和对象存储；
- 邮箱验证、密码重置、邀请邮件；
- 产品事件埋点与企业激活漏斗。

### Phase C：可规模销售

- 企业 Logo、颜色、欢迎语和自定义域名验证；
- SSO / SAML、SCIM、成员移除和所有权转移；
- 套餐、支付、发票与试用到期策略；
- 数据导出、租户删除、保留策略和 DPA；
- 监控、告警、SLA 与多实例扩展。

## 8. 商业假设

先招募 3–5 家设计伙伴，不急于接入支付。建议假设套餐如下，并通过访谈验证：

- 试用版：14 天、3 名成员、1 个知识库、200 份文档；
- 团队版：按企业/月收费，成员数、文档量和查询量设软配额；
- 私有部署版：部署、升级和运维服务单独报价。

访谈必须追问客户最近一次查找内部资料失败的真实经历、耗费时间、现有工具、采购人和可接受预算，避免只问“你会不会用”。

## 9. 发布验收

- 新企业注册后只看到自己的默认知识库；
- 所有者可创建邀请，待邀请列表可见；
- 邀请链接在企业网址打开后显示企业、邮箱和角色；
- 接受邀请后 token 二次使用失败；
- 只读成员可以问答，但服务端拒绝创建知识库、上传和评测；
- 企业 A 的成员不能访问企业 B 的知识库和成员；
- 后端全量测试、前端测试、Lint 和生产构建通过；
- 数据库迁移在空库和已有数据卷上都可重复运行。
